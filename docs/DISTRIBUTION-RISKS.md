# ScapeLite: risks of a small tester distribution

Research date 2026-10-27, version 0.4.0 (unpublished). Scope: handing the installer to a FEW SELECTED TESTERS (people the owner knows, Windows, Steam copy of the game). Not covered here: several instances relaying the same clan chat into one Discord channel (another agent owns that design; section 3.8 only notes how the guards interact).

"Wulf" stands for the owner everywhere. Nothing in this file is a secret, a real name, a handle or a webhook URL.

## How to read this

* **L** = likelihood that it happens to at least one of ~5 to 10 testers: High / Medium / Low. **I** = impact if it does: High (data leak, banned account, broken game, lost trust), Medium (feature broken, wasted time), Low (cosmetic, rare).
* **Evidence tags:** `[verified]` I ran or read the thing and saw it. `[code]` read in the source, not run. `[unverified]` plausible, needs a test on a clean machine (roadmap `repo-003`).
* **Owner / effort:** `Dev` = coding or docs work Claude can do, `Owner` = a decision or an account only Wulf can make. Effort S (under 2 h), M (a day), L (several days).
* Roadmap ids in `repo-0xx` style point at items that already existed; new ideas added by this research are tagged `distribution` (see section 8).

## 1. Install and update

**I-01 Unsigned installer: SmartScreen and Defender.** L: High, I: Medium. Windows shows "unknown publisher / Windows protected your PC"; some AV products quarantine unsigned Electron installers or the process behaviour (`cmd /c start steam://`, `powershell Get-CimInstance`, `taskkill /F`, a hidden Node child that talks to another process' debug port; `launcher.js`). `signAndEditExecutable: false` also means the exe carries no version/company metadata, which does not help reputation. Tester notices: red/blue screen on first run, installer vanishes, "Threat found" toast. Mitigation: tell testers beforehand (screenshots of More info, Run anyway), ship the SHA-256 next to the file, build with metadata in CI (the Actions runner can set `signAndEditExecutable: true`; it was turned off for local Windows builds without symlink rights), submit the file to Microsoft's false-positive portal before sending, keep an "exclusion folder" paragraph in the guide. Signing: a certificate costs money; free routes for open-source projects (for example a foundation-run signing service) usually require a public repo WITH a licence and a review, and eligibility changes, so treat as `[unverified]`. Owner: decision unsigned-vs-signed (`RELEASE-CHECKLIST` item). Effort S for metadata + portal, M-L for signing.

**I-02 Per-user install, one-click NSIS.** L: Low, I: Low. `perMachine: false`, `oneClick: true`: installs to the user's profile (`%LOCALAPPDATA%\Programs\ScapeLite`), no admin prompt, data in `%APPDATA%\ScapeLite`. Good for testers. Risk: installing from an elevated prompt installs for the admin account instead; a second Windows user gets their own copy and their own data (see 3.8). Mitigation: say "double-click it, do not run as administrator" in the guide. Dev, S.

**I-03 Paths with spaces or non-ASCII user names.** L: Medium, I: Medium. `[code]` Most spawns use `execFile` with argument arrays (safe with spaces). Concerns: (a) `launcher.js` reads `reg query` output with Node's default UTF-8 decoding of a console-code-page string, so a Steam folder with accented letters can come back garbled, `existsSync` fails and detection falls back to the two default folders, then reports "Scapewatch was not found"; (b) `libraryfolders.vdf` paths are un-escaped manually and decoded as UTF-8 (fine); (c) `status-server.js` spawns `explorer.exe` with the folder (fine); (d) NSIS Unicode paths are fine. `[unverified]` for all. Mitigation: test with a Windows account named with a non-ASCII letter and a space, and a Steam library on `D:\Spiele\Ä`; read the registry through `reg query` with `chcp 65001` or via PowerShell JSON; add the manual "game folder" setting (roadmap `repo-013`). Dev, S for the test, M for the fix.

**I-04 Steam / game not found.** L: Medium, I: Medium. Detection needs Steam in `HKCU\Software\Valve\Steam`, an `appmanifest_*.acf` whose `name` matches /scapewatch/i, and `Scapewatch.exe` in the install dir. Fails for: non-Steam copy (website or standalone), library on a drive Steam does not list, Steam under another registry hive, Proton/Linux/macOS (unsupported: `reg`, `tasklist`, `powershell`, `explorer.exe`, `taskkill` are Windows-only), Steam Deck. Tester notices: "Scapewatch was not found in your Steam libraries", dashboard stays on "no game". Note the game is also playable in a normal browser at `play.scapewatch.com`: ScapeLite cannot attach there at all (no debug port); say so in the guide. Mitigation: first-run help with a manual path, a clear "supported: Windows + Steam" statement, a status message that tells browser players it does not work (roadmap `repo-013`, `repo-019`). Dev, M.

**I-05 Game started without the debugging port.** L: High (every normal Steam launch), I: Medium. Flow: the tray app and the supervisor start; the "game guard" (`launcher.startGuard`, every 1.5 s) lists `Scapewatch.exe` processes with `tasklist`, waits 1.8 s, reads the main process command line through PowerShell/CIM, and if there is no `--remote-debugging-port` it runs `taskkill /IM Scapewatch.exe /F` and relaunches through `steam://run/<appid>//<flags>/`. `autoRelaunch` defaults to ON, at most 2 restarts per 3 minutes. Risks: (a) the tester's game is killed without asking: a tester who just logged in and is mid-trade or mid-raid lobby is surprised, may lose an unsaved raid join, and sees the "Steam: game stopped" flicker; (b) `tasklist` runs 40 times a minute for as long as the supervisor lives, which is both a measurable (small) CPU cost on weak PCs and an AV-heuristic signal; (c) if Steam is not running `steam://` may show Steam's own start-up and a login dialog, and the 90 s wait elapses with a "connection did not come up" message; (d) if the tester also pasted the old manual launch option into Steam, Steam and our URL both carry flags (duplicate flags are harmless for Chromium, `[unverified]` for Steam's argument merge); (e) if the game runs elevated and ScapeLite does not, the command line may be unreadable (no action, plugins never load) and `taskkill` is denied. Mitigation: default the guard to "ask first" (a toast with a Restart button) for the tester build, show a clear dashboard line "game started without ScapeLite; press Restart", slow the poll or use a process-start event, never kill while a raid or fortress is active if the bridge can tell. Dev, M. Decision for Owner: is auto-restart acceptable at all given "tools must not act for the player"? Closing the game process is not an in-game action but it is the most intrusive thing the tool does.

**I-06 Port 9222 busy or another Chromium app.** L: Low, I: Medium. `launcher.portOpen()` treats ANY answer on `127.0.0.1:9222/json/version` as "game is ready"; the watcher then picks the first page whose URL matches /scapewatch/i from `/json`. With another Chromium/Electron app or an old Chrome started with the same port, the dashboard says Connected-ish but nothing loads, or (worse) plugins are injected into an unrelated page whose URL merely contains the word. Also two copies of the game cannot share the port: a second launch (second account, a "multi-box" tester) silently has no port. Mitigation: verify the target (`type: page`, url host `play.scapewatch.com`, `Browser` header is Electron) before saying ready, and use a random free port passed to the game and remembered (roadmap `repo-012`). Dev, M.

**I-07 Port 7777 or 80 taken.** L: Medium (7777 is a default of several game servers and tools), I: Medium. `[code]` `status-server.js`: bind errors on 7777 are only logged, the supervisor carries on and starts the watcher anyway. In `app/main.js` `get()` resolves `{}` on a non-JSON answer, and `{}` is truthy, so `ensureSupervisor()` returns "attached" when a FOREIGN service answers on 7777: the tray believes ScapeLite is running, opens its window on someone else's page, and never starts a supervisor. Port 80: another web server (IIS, XAMPP, a dev tool) on `127.0.0.1:80` makes `http://scapelite.localhost/` open the wrong site; only a log line says so. Mitigation: `get('/status')` must check for a ScapeLite-shaped answer (`supervisor` key), fall back to another port and write it where the in-game plugins can find it (they hard-code `http://localhost:7777`), and give the supervisor a hard exit when it cannot bind (also a natural single-instance lock, see 3.8). Dev, M.

**I-08 Firewall prompts.** L: Low, I: Low. Everything listens on loopback only, which does not trigger the Windows Firewall "allow access" dialog; outbound connections are Discord, GitHub raw (plugin install on request), GoatCounter, `play.scapewatch.com`. `[unverified]`: confirm on a clean VM that no prompt appears, and that corporate/school machines with TLS inspection do not break the Discord posts (they will just fail with a visible error in Discord health).

**I-09 Antivirus on the debugging port.** L: Low-Medium, I: Medium. Some security suites flag a non-browser process attaching to a debug port or "script injection into another application". Tester notices: ScapeLite connects for a minute then the AV kills `ScapeLite.exe`, or the game's Steam overlay misbehaves. Mitigation: explain in the guide exactly what the connection is (a loopback WebSocket to the game's own page, nothing written to the game's files), list the exclusion path, collect which AV products testers run. Owner/Dev, S.

**I-10 Admin versus normal.** L: Low, I: Low. See I-05 (e). Also: Steam run as admin and ScapeLite not = no process info, no restart. Guide line: run both normally.

**I-11 Auto-start at login and duplicates.** L: Medium, I: Medium. The tray's "Start with Windows" uses Electron's login item (a `Run` registry value). The older `start-watcher-hidden.vbs` / `start-scapelite-tray.vbs` shortcuts from the source-checkout days are not part of the installer, so a fresh tester has none, but the owner and any tester who ever ran from source can have both. `[code]` Mitigations exist: `ensureSupervisor()` attaches to a running service and `single-instance.js` keeps one supervisor per data folder. Remaining holes: the `.vbs` hard-codes `C:\Program Files\nodejs\node.exe` (fails silently if Node is elsewhere), and the installed app and a source checkout use DIFFERENT lock folders (see 3.8). Uninstall does not remove the login item `[unverified]`, so a dead `Run` entry may remain pointing at a deleted exe. Dev, S (test + doc).

**I-12 Uninstall leaves files and state.** L: High (by design), I: Medium. `deleteAppDataOnUninstall: false`, so `%APPDATA%\ScapeLite` stays: settings, logs, extracted game data (about 20 MB plus icons) and, importantly, the Discord webhook config files (secrets) stay on a tester's disk after they "removed" the tool. Plus localStorage in the game's own profile (Task Log, chat history of other players, layouts, `cc-*` keys) is untouched; ScapeLite cannot clean that from the uninstaller. Mitigation: documented reset steps now; a tray item "Remove ScapeLite data..." that deletes `%APPDATA%\ScapeLite` and asks the page to clear its `cc-*` keys (roadmap `log-004`, `feat-088`); an uninstall checkbox. Dev, M.

**I-13 Update channel: what it checks, rollback, bad update.** L: Medium, I: High. `[code]` Git installs: `git fetch` + `git pull --ff-only` (+ `npm install`); manifest installs: a JSON `{version, notes, downloadUrl}` and a link, nothing is downloaded or applied by the app; the installed default is NOT configured (see table). Consequences for testers: (a) nobody is told about a new build, you must message them; (b) a bad build cannot be pulled back by a switch: rollback = reinstall the older installer, and the older build reads the newer build's settings (see I-14); (c) there is no signature or checksum check on the manifest or the download, only `https://` for the link; (d) the NSIS installer replaces files in place, and the running tray/supervisor/watcher (all named `ScapeLite.exe`) must be closed first; electron-builder asks, but a hung hidden supervisor can block the upgrade `[unverified]`. Mitigation: for a handful of testers do it manually and deliberately: versioned installers, a CHANGELOG line per build, keep the previous installer, publish SHA-256, and decide on a feed (`repo-011`) only when the group grows. Owner decision.

**I-14 Version skew between testers and settings migrations.** L: Medium, I: Medium. Plugin settings live in the game page's localStorage (`__ccPluginSettings`, `cc-*` keys) and in JSON files in the data folder. `[code]` There is no schema version on the config/state files, no migration framework (one ad-hoc migration exists for Discord ping roles, `panel-resize-watcher.js` ~line 1491), and no "config is newer than this build" guard. Testers on different builds report different bugs; an older build may reset or mis-read a newer file. Mitigation: a `schemaVersion` in each state file with a one-line rule ("never change the meaning of a field inside a version"), ignore-and-warn when newer, and put the build number in every report (see 4.2). Dev, M.

**I-15 Data folder and migration from a source checkout.** L: Low for testers, High for the owner, I: Medium. A source checkout keeps state next to the code (`overlay/*.json`, `Logs/`, `data/raw`); the installed app uses `%APPDATA%\ScapeLite`. There is no importer: an installed copy on the owner's own machine starts empty (it re-extracts game data from the asar, which is fine) and webhook configs must be re-entered. Worse, running both at once = two supervisors (see 3.8). Mitigation: a one-time "import from folder" button or a documented copy list; on the owner's machine, stop the checkout before testing the installer. Dev, S-M.

**I-16 Installer size and many small files.** L: Low. `asar: false` ships thousands of loose files (97 MB installer); Defender scans them on first launch and the first start can take noticeably long on a slow disk. Mention in the guide ("first start can take a minute").

**I-17 Personal files packed into the installer.** L: Medium, I: High. `electron-builder` packs the working tree through the `build.files` globs, not git. The list is a deny-list; files that appear later are not on it. Today `overlay/discord-test-webhook.json` (a real test webhook, git-ignored) and `overlay/*.lock` are not excluded, so `npm run dist` on the owner's PC would ship them; the 0.3.0 installer in `dist/win-unpacked` is clean, the GitHub Actions build (clean checkout) is clean. Tester notices: nothing, which is the problem: the first sign would be a webhook posting spam. **Status 2026-10-27: done** (`docs/PACKAGING.md`): `build.files` is an allow-list, the `afterPack` guard fails the build on a hit, `npm run verify:package` re-checks any output, the publish script scans the files it publishes. Original mitigation: build tester installers only from a clean checkout (CI, or `git archive` into an empty folder), switch to an allow-list or add a post-build scan of `dist/win-unpacked/resources/app/overlay` that fails on `*config.json`, `*state.json`, `*webhook*`, `*.lock`, `*.log`, `*.bak`. Dev, S.

## 2. Security and privacy

**S-01 The remote debugging port.** L: Low-Medium, I: High. What it exposes: full control of the game page (read the DOM and storage including the game session, run any script, click) to anything on this machine that can reach `127.0.0.1:9222`. Cross-origin web pages: blocked IF the flag is dropped (verified above); with `--remote-allow-origins=*` a page in the user's normal browser could open the WebSocket if it learned the target id, which needs the `/json` list (not readable cross-origin, DevTools sends no CORS headers) and Chromium's Host check blocks DNS rebinding, so practical exploitability was low, and it is now closed: the flag is narrowed to the debugger's own origin (the watcher needs no flag at all). Other local users and any local program remain able to attach: inherent to the debugging-port design, cannot be fixed by flags; this is the honest residual risk and belongs in the tester guide ("while the game runs with ScapeLite, any program on your PC can control the game page; do not run it on a shared or untrusted PC"). Binding is already loopback. Further hardening: random port instead of 9222 (obscurity only). The dashboard's "DevTools" link needs the inspector's own origin allowed (`[verified]` 2026-10-28: refused with no flag, accepted with the narrowed list), which is why the flag is narrowed instead of dropped. Roadmap `repo-009` (note added), `repo-012`. Dev, S.

**S-02 What ScapeLite reads and stores.** L: High (it does), I: Medium. Page side: the game's own state (skills, bank, quests, queue, clan members, online players), chat lines (other players' names and text, last 400 in localStorage `cc-chat-log:v1`), the Task Log (2000 records, no names), Fortress and drop history. Files side: `Logs/` with names of clan members in the Discord channel logs (verified), `player-icon-cache.json` (avatars), Discord state files (ids of relayed events). Nothing leaves the PC except what is configured (Discord) and the usage ping. Gaps: no "what is stored" screen (`log-005`), no one-click export/delete (`log-004`), and chat history of other people persisting in the browser profile for good. Mitigation for testers: tell them exactly this list; add a "Delete my data" action; make chat history opt-in or shorter. Dev, M.

**S-03 Dashboard reachable by other local users.** L: Low, I: Medium. Loopback only, so not by the network; but another Windows account on the same PC (or any local program) reaches `127.0.0.1:7777` and the control API accepts requests with no `Origin`: it can stop the service, restart the game, press "install plugin from GitHub link" (which downloads code that runs inside the game page once the player enables it), read `/status` (recent log lines, Discord health, no webhook URLs) and `/api/logs/*`. Web pages cannot (see check table). Mitigation: a per-launch random token that the tray/watcher/page get at start and the control API requires (refuse Origin-less calls), or at minimum document "single-user PC". The `/status` CORS grant to the game origin also lets any script in the game's page read recent log lines; trim `recentLog` from the cross-origin view. Dev, M. Priority P3 for a handful of known testers.

**S-04 Usage ping and GDPR.** L: High (on by default), I: Medium for trust. For EU/UK testers an IP address is personal data and a third-party request with it made without a prior opt-in is a consent problem even when GoatCounter does not store the IP. The first-launch setup asks, but the default answer is "on". The website FAQ says "Does it send my data anywhere? No ... only the update check" and, separately, describes the ping: contradictory, and the update check does not exist in installed builds. Mitigation: default OFF for the tester build (testers are reachable people: ask them for counts directly), one consistent statement in the FAQ, README, tour and `usage-ping.js` header, and keep the 'no data, no id' promise. Owner decision, Dev S. (Roadmap `log-006` is the later opt-in counter.)

**S-05 Webhook URLs on disk.** L: Medium, I: High. Plain JSON in `%APPDATA%\ScapeLite` (or `overlay/` in a checkout), git-ignored, redacted from logs (`logging/redact.js`: webhook, token, bearer, secret-looking keys, home folders). Risks: a tester zipping the whole data folder for a bug report includes the webhooks; a tester screen-sharing the Settings page; `watcher.log` is written with raw text (line 195 of `panel-resize-watcher.js` does not pass through the redactor; the structured `Logs/` path does) so an error message that embeds a URL would land there unredacted `[code]` (0 hits today). The anyone-with-the-URL property of a webhook (post, edit, delete) is documented in `CLAN-STATUS-BOARD.md`. Mitigation: redact `watcher.log` too and rotate it (`log-002`), the diagnostics bundle must never include config files, tell testers which files are secret, offer "rotate webhook" instructions. Dev, S.

**S-06 Logs containing names and paths.** L: High, I: Low-Medium. Verified names of other players in Discord logs; the redactor replaces `C:\Users\<name>` with `<user>`. A tester who attaches raw logs publishes other people's in-game names. Mitigation: the diagnostics bundle includes only the last N redacted lines of System/Watcher/Errors, never Discord/Chat channels, and says so. Dev, M (same work item as 4.2).

**S-07 Discord features that post other players' content.** L: Medium, I: High (community). The chat relay can mirror plain chat (kind `chat`), drops, unlocks, level-ups; the clan board posts a member's current activity; hiscores and raid summaries name clan members. Concerns: (a) consent of the people named; (b) Discord's rules about automating posts from a user-controlled tool through a webhook are fine technically (webhook, not a self-bot, no user-token automation), but mirroring private chat into a channel the speakers do not know about is a social problem; (c) several testers in one clan = duplicates (other agent). Mitigation: plain-chat mirroring OFF by default, a first-enable dialog ("tell your clan; messages of other players will be copied to this channel"), per-field opt-in (already the rule in `DISCORD-FEATURES.md` section 8: confirm it is implemented for every feature). Owner + Dev, S. Also `allowed_mentions` is already forced to `{parse: []}` in `discord-sender.js`: good.

**S-08 Game developers' stance and the "tools must not act for the player" rule.** See 2.8 and section 5. Highest community risk.

**S-09 Community plugin installer.** L: Low (the list is empty, install needs a GitHub URL typed in), I: High. Plugins run inside the game page: they can read the game's local storage (session data) and talk to the internet, and could be social-engineered onto a tester ("install my plugin from this link"). The preview scan is a heuristic (it flags `fetch`, `eval`, click/dispatch, URLs) and will miss obfuscation. Mitigation: for the tester build hide "Install from GitHub link" (or keep it behind `devMode`), and say so in the guide. Dev, S.

**S-10 Chromium/Electron security updates.** L: Medium over time, I: Medium. ScapeLite ships its own Electron 37 runtime; its tray window only loads loopback pages, but nothing updates it except a new installer. Low for a few weeks; note an expiry date for tester builds.

**S-11 Gear-calc localStorage overwrite.** L: Medium, I: Low. `game-bridge.js` `calcRefresh` writes the game's own calculator snapshot key (`U.STORAGE_KEY`) and loads the calculator in a hidden iframe to read "Avg DPS". That replaces whatever the player had saved in the in-game Gear Calc and runs a hidden extra page. Display-only in spirit, but a side effect on the player's data; list it in the known issues and prefer the local DPS maths already present (`gearDps`). Dev, S-M.

### 2.8 The click and event dispatch audit

The README, website and `PLUGINS.md` rule 1 say ScapeLite "never clicks, selects, submits or plays for you". That is not literally true. Every place that clicks or dispatches events into the game (grep `.click()`, `dispatchEvent`, `new MouseEvent/PointerEvent/KeyboardEvent` over `overlay/`, plus the bridge's writes), classified:

**A. Navigation mirror, started by the player's click on a ScapeLite control. Covered by the developer's reported OK (navigation buttons only).**
* `alert-bell.js` `pressTab` (allow-list `NAV_OK`, only on the player's click on a bell row), `raid-alert.js` `openRaids` (the toast button or notification click opens the game's Raids tab; the player presses Join).
* `ui-bar.js`: skill cell, quest slot, tab buttons and the card corner buttons pass the player's click to the game's own control (opens a window).
* `window-dock.js` (the cross on the map presses the game's map button), `ui-scale.js` (Escape closes the top ScapeLite box), `sidebar-tabs.js`, `ui-layout.js` collapse, `modal-resize.js` close.
* `queue` navigation: `panToRow`, `openQueued` (pan the map), Ctrl-click on an option.

**B. State-changing mirror: the player clicks a ScapeLite control and ScapeLite performs the click on the game's own control. NOT navigation; not covered by an explicit developer OK I know of.**
* `ui-queue.js`: `selectOption` (pick a task option in a queue slot), `doReroll` (spends reroll credits, `.uq-cost-badge`), `reorderSlot` (synthetic pointerdown/move/up drag on the game's rows), `cancelQueued`, roll controls (`ctlClick`: how new tasks roll, Auto Loadout) and slayer master choice, `pickLoadout` (changes the equipped combat loadout). The Slay/roll controls come very close to the developer's list of forbidden things ("select tasks, change lever/location weights"), only differing in that a human clicked a button in our window.
* `ui-bar.js`: loadout pick, friends add (types a name into the game's input and sends Enter).
* `chat-plus.js` `send`: sets the game input's value and dispatches input/Enter, so a message typed in our box is sent in the game; `chat-plus` room picker clicks the game's room list; `bridge.setChatChannel` writes the game's active chat channel.
* `bank-tools.js`: Remove placeholders and Sort/Insert style buttons pass the click on.
Safeguards seen: handlers check `ev.isTrusted` in places (a synthetic click cannot start these), a freshness guard (`rowsFresh`) refuses when the game's panel is stale, every call is one click per player click, no timers re-trigger it.

**C. Automatic (no click on a ScapeLite control for that exact action).**
* `panel-fuse.js`: when the player opens/closes a game panel, ScapeLite presses the partner panel's tab button or close button so fused panels open and close together (UI visibility only; `gLock` throttles it). Display-layout only, but it is the one automatic click.
* `ui-kit.js` `popupClose`: dispatches synthetic pointer/click events on `document.body` to dismiss a game pop-up menu after the pointer leaves.
* `game-bridge.js`: `refreshQueuePanel` calls the game's `Q.update()` (a redraw), `setChatChannel`, the gear-calc localStorage write and hidden iframe (S-11).
No timer or observer starts a game action (queue, reroll, loadout, chat, trade, claim) on its own: confirmed by reading every call site above, but a periodic re-grep belongs in the release checklist.

**Flags.** (1) Class B is the exposure: it is "tool presses buttons that change game state", and from the game's side a synthetic click is indistinguishable from a macro's. If the developer disagrees, ScapeLite is on the wrong side of a ban rule and testers carry the account risk. (2) The public wording is inaccurate (`feat-030` plans to list the forwards in `PLUGINS.md`; also fix README, website FAQ, plugin descriptions). (3) The community plugin scanner calls clicks "not allowed for ScapeLite plugins" while our own do it: the rule needs one honest sentence ("only on the player's click, only on the game's own control"). Mitigation: get the developer's written position on class B specifically (section 5), ship a "Display-only mode" setting that turns every class B/C forward off (and make class B default-off for testers until the answer is in), and describe it truthfully.

## 3. Compatibility and robustness

**C-01 The game updates and breaks selectors or the bridge.** L: High over weeks, I: High. Verified: the Steam app loads the live web client, so a server-side deploy changes the DOM, CSS classes and the internal objects (`G`, `D`, `C`, `Q`, ...) the bridge finds with `Runtime.queryObjects`, with no Steam update and no change in the asar the data extractor watches. What breaks: the bridge (`__ccBridge.ok()` false, every plugin that needs it degrades), selectors (`.panel-tab-btn`, `#unified-queue-panel .uq-row`, `.chat-panel .chat-input`, `.loadout-sel-slot`), text matchers (`Avg DPS` in the calculator). How we notice today: the status light and the dashboard card show the bridge and plugin load state; plugins mostly catch errors and show nothing. How we do not notice: nothing records the game's version or a client fingerprint (no hit for a game-version stamp anywhere in the watcher or logs), there is no self-check that says "queue panel selector X not found", no "compatibility report" button, and the bug report omits the game version. Mitigation: (1) stamp every log session and every bug report with the wrapper version (asar `package.json`) AND a client fingerprint (hash of the main script URL or of a few key class names) read at inject time; (2) a self-check run after inject that lists, per plugin, the selectors/objects it needs and whether they were found, shown as a health card and in the diagnostics bundle; (3) a "Compatibility report" button that copies it; (4) per-plugin kill switch that already exists (marketplace Remove) plus an "auto-disable after 3 consecutive errors" breaker. Testers will be the first to notice: tell them to report "after the game's update at <time>". Dev, M-L. Highest return for support.

**C-02 Screen resolutions, DPI, scaling, multi-monitor.** L: Medium, I: Medium. Panel positions and sizes are stored in pixels in localStorage; layout presets and `cc-panel-fuse` are saved per profile. A tester with a smaller window, a different Windows scale (125/150/200%), a second monitor unplugged, or a 1366x768 laptop can end up with panels outside the viewport. `panel-resize.js` mentions the game's own drag clamp and the scale transform; `ui-layout` has "Tidy up" and "Reset all" (with one undo) and layouts.js a "Game default" preset. Not found: automatic re-clamp on window resize for ScapeLite's own boxes `[unverified]`. Mitigation: test matrix (100/125/150/200% x 1366x768, 1920x1080, ultrawide, game windowed/fullscreen/borderless, monitor switch); an "Everything is off-screen" panic button reachable without a panel (tray menu entry that sends Reset all). Also a memory note: never move game panels in tests without backing up `cc-panel-fuse` (corruption incident). Dev, M.

**C-03 Low-end PCs.** L: Medium, I: Medium. The mod runs inside the game page (JS timers, MutationObservers, a frame loop for overlays) plus a watcher process (CDP polling every few seconds), the supervisor, the Electron tray and the game guard's 1.5 s `tasklist` loop. The status light shows measured per-plugin CPU (sampling profiler) and an Eco mode (`lifecycle.js`, `cc-eco`) exists that pauses page work while the window is hidden; the Eco mode test is still open (`feat-002`) and `log-014` tracks a known 80 ms hitch of the layout editor. There are no published minimum specs and no numbers for a weak laptop. Mitigation: measure on the weakest machine available (idle for an hour, then a raid), publish the numbers, default the heaviest plugins off for testers (the marketplace only enables the recommended set already), and tell testers about the status light's CPU breakdown. Dev, S-M.

**C-04 Different accounts and progress (fresh account, empty data).** L: High (new alts, testers who just started), I: Medium. A brand-new account has no bank, no quests, no clan, no friends, no queue; plugins that read those structures may show errors or blank cards (`feat-027` "cards on a fresh install"). Also a free-to-play flag exists in the game (`feat-013`): features gated by membership. Mitigation: run every plugin on a new account with empty state, check `Logs/Errors/`, fix nulls; list "needs X" per plugin in the marketplace. Dev, M.

**C-05 localStorage is per game profile.** L: Medium, I: Low-Medium. Settings, layouts, the Task Log and chat history live in the game's Electron profile for `play.scapewatch.com`: clearing site data, the wrapper's own safe-mode reset (its `safeMode.js` handles black windows by resetting caches in `userData`) or reinstalling the game wipes ScapeLite's page-side state. The Task Log is rebuilt from `Logs/Tasks/*.jsonl` (already done), layouts and settings are not. Two different Windows users or two game profiles do not share settings. Mitigation: export/import of settings (`display-options.md` area), say so in the guide. Dev, M.

**C-06 Conflicts with other mods.** L: Low now, I: Medium. There is no other mod ecosystem for this game that I know of; a userscript/extension or another CDP client (a second tool attaching to port 9222) would run in the same page: two injectors double-patch, and two CDP clients can fight over `Page.addScriptToEvaluateOnNewDocument`. Also a tester's browser extension is irrelevant (the Steam app has none). Mitigation: namespaced globals and teardown-on-reinject are already the pattern (`__cc*`); ask testers not to run other debugging tools at the same time. Owner S.

**C-07 Game in another language.** L: Low, I: Low `[unverified]`. Several matchers use English text (calculator row `Avg DPS`, names for tooltips and bank targets, `findTarget` by item name, chat `data-category`). If the client has a language setting, those fail silently. Check whether the game ships languages (the chat has a "language/world" room picker, which is a chat room, not a UI language). Dev, S.

**C-08 Mobile layout.** Not applicable: ScapeLite needs the Steam desktop wrapper and a debug port; the game's mobile/browser versions cannot be reached. Say so in the guide (I-04). The dashboard and marketplace are desktop pages; the website has a mobile layout.

**C-09 Crash loops.** L: Medium, I: Medium. The incident: the hidden supervisor's session was dropped by the system and the watcher exited six times in 15 s with code 3221226091 (`0xC000026B`, a DLL initialisation failure in a hidden window); since commit `b0a4bdc` the supervisor keeps retrying once a minute after five quick retries. `[code]` Good: bounded, logged, visible in the dashboard. Remaining: an update that crashes at start (a syntax error in a plugin) would loop forever once a minute with no tester-visible error beyond the status light; the watcher injects plugins one by one, so a throwing plugin should not block the others (`[unverified]` for a syntax error in a core plugin). Mitigation: safe mode (4.5) plus after N crash cycles stop injecting plugins and say why. Dev, M.

**C-10 Supervisor and tray ownership.** L: Medium, I: Low. `[code]` Menu item "Quit ScapeLite (keep service running)": when the tray instance started the supervisor itself (the normal case: `ownsSupervisor` is true) `quit()` stops the watcher and kills the supervisor anyway, so the label is wrong; only an attached (already running) service is kept. Result: a tester closes the tray "keeping the service" and the Discord relay stops, or the reverse. Fix the label or the behaviour (`repo-007` covers tray adopting a hand-started supervisor). Dev, S.

**C-11 Two copies running (single-instance coverage).** L: Medium, I: High for Discord (double posts), Low otherwise. `[code]` The lock is a pid file in the per-user data folder (`overlay/` in a checkout, `%APPDATA%\ScapeLite` installed). It covers: two starts from the same checkout; two starts of the installed app for the same Windows user (plus Electron's own single-instance lock for the tray). It does NOT cover: (a) installed app + source checkout on one machine (different lock folders; both start a supervisor and a watcher, both post to Discord; the owner's PC is the likely case); (b) two Windows users logged in at once (each has an own data folder; the second cannot bind 7777 but, as shown in I-07, still runs its watcher and attaches to the same game port); (c) two machines (that is the other agent's topic); (d) a stale lock whose pid was reused by an unrelated live process after a crash or power loss: `alive(pid)` only asks the OS whether the pid exists, so the new supervisor exits silently ("another supervisor is already running") and ScapeLite never starts until the file is deleted. Mitigation: make "could not bind 7777" a hard exit (a free machine-wide lock), compare the pid's image name/start time before honouring a lock, write the exit reason to the log AND the tray dialog. Dev, S-M.

**C-12 Disk usage of logs and state.** L: Medium over months, I: Low-Medium. Structured logs: `keepDays` 14, `historyDays` 90, `maxFileMB` 5, `maxTotalMB` 100 per channel (so up to about 1 GB across ten channels in the worst case, in practice tens of MB: this checkout's `Logs/` is 7.6 MB). `watcher.log` is unbounded (2.3 MB here and growing; `log-002`). `digest-state.json` grows. localStorage: Task Log about 0.7 MB, chat 400 messages; the browser limit of about 5 MB is shared with the game. Mitigation: rotate `watcher.log`, lower the tester defaults (`maxTotalMB` 30), a "storage used" line in the dashboard (`log-005`). Dev, S.

**C-13 Memory growth.** L: Low-Medium, I: Medium. A profiled long session once found 35 to 70 stacked copies of listeners (fixed by `lifecycle.js` scopes, which dispose old instances on re-injection). The re-injection pattern (every watcher restart re-injects) is the leak risk. Mitigation: a soak test of 8 hours with periodic plugin restarts watching JS heap and DOM node count (the status light already reports both), in the tester guide say "restart the game once a day if it feels slow". Dev, S.

* [ ] `ScapeLite Setup <version>-tN.exe` built from a clean checkout in CI, with exe metadata; the build id shown in the app.
* [ ] `SHA-256` text file (and the same hash in the message you send).
* [ ] **QUICK-START.md** (one page): what it is and is not (display only, Steam on Windows only); install in 3 steps with SmartScreen screenshots ("More info, Run anyway"); how to launch the game (Launch Scapewatch button; what the "restarted your game" message means); the welcome tour; the 5 plugins to try first; what to try and report.
* [ ] **Rules page**: the display-only rule; not advertising or posting screenshots in the official Discord; Discord relay consent (tell the clan); do not share the installer; tester agreement (L-07).
* [ ] **KNOWN-ISSUES.md** (draft list: unsigned installer warnings; Windows only; browser/mobile version unsupported; game updates can break plugins until we patch, with the safe-mode steps; auto-restart of the game; Gear Calc saved state is replaced by the Avg DPS helper; chat history of other players kept locally; low-end PC cost; panels off-screen after a resolution change, use Reset all; updates are manual).
* [ ] **How to report a bug**: Report button, then Copy diagnostics (or Save diagnostics file), then send it in the private channel with: time, what you did, what you expected, which plugin, build id. What is in the file (list) and what is not (webhooks, chat).
* [ ] **Privacy sheet**: what is stored where (`%APPDATA%\ScapeLite`, the game's browser profile), what leaves the PC (nothing unless Discord is configured; usage ping state), how to delete everything.
* [ ] **Troubleshooting**: dashboard says "Waiting for the game", port in use, game found/not found, safe mode, clean reset, how to open the Logs folder, which logs NOT to send.
* [ ] **Uninstall and reset steps**, including the login item and `%APPDATA%\ScapeLite`.
* [ ] **Update procedure**: how you will tell them (message), how to install over the old one (close the tray first), how to roll back (keep the old installer).
* [ ] **Contact and feedback channel** (private, not in the official Discord); expected response time; expiry date of the build.
* [ ] **A tester record for the owner**: Windows version, AV product, display scale, Steam library location, account age; plus a sheet of what each tester ran (plugins) so reports can be compared.
