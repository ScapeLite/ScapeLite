Method: bundle.js grep + read-only CDP evaluation (`window.__ccBridge.shape`, window globals, a one-off queryObjects lookup of G/D/Y/U). Nothing in the game was clicked or mutated. VERIFIED = checked against live data; CODE = read from code; SPEC = guess.

## PART A. Fortify tree and the Fortress

### A0. Key finding
The **Fortify tree has no effect on Fortress (gauntlet) waves, army stats, deposits or rewards.** Every Fortify node is a skilling/economy bonus (movement, success, double-gather, save-material, XP, action time, food heal, barter XP). "Fortify" is the raid skill trained inside the Fortress (skilling raid; `raids.json` id `gauntlet`, display name "Fortress", `kind:"skilling"`, `endless:true`); its level = talent points. The Delve tree is the same construct for combat dungeons (Delve skill is trained by damage dealt in dungeons). Bundle release note: "Added Delve and Fortify talent trees. Spend points on combat and skilling bonuses, and reroll to respec". (CODE)

### A2. Tree schema (VERIFIED from live data)
```
tree = { skill, name, starter:{id:"fortify_n0",tier:"large"}, pointsFreeStart:1, purchasable:120, basePurchasable:99,
         extendedPurchasable:120, clusters:[10 fortify / 11 delve], nodes:[120], layoutExtensions:[2 drawing descriptors] }
cluster = { id, name, effect, unit, scope:"global"|"raid", desc, negative:bool, total, nodeIds:[...] }
node    = { id:"fortify_nK", tree, cluster, tier:"small|medium|large", effect, value:number, slot:K,
            requires:[parentId], requiresLevel?:100|110, negative?:true,       // fortify momentum nodes: negative:true (value is positive seconds)
            skill?:"heft"..., head?:"+1 Heft level" }                          // delve effLevel nodes only
```
* Graph is a pure tree rooted at the starter: every node has exactly one entry in `requires` (all lengths 1). Max depth 14. Root children: n1 n2 n3 n5 n7 n9. Prereq rule (`prereqsMet`): the parent is allocated or is the starter. Nodes n100..n120 form the extended ring.
* Cost: always 1 point per node. No ranks, no keystones, no multi-rank nodes, no exclusivity. `value` is the whole effect; tier only scales it.
* Level gates: 21 nodes per tree carry `requiresLevel` 100 or 110 (n100-n120). Others ungated.
* Points: `pointsAvailable = skill level`; points left = level - allocated.length. Base cap level 99 (99 purchasable + free starter); extended cap `maxLevelFor = 120` (XP 50.0M at 99, 400M at 120). `G.xpTable.xpForLevel[L]` cumulative XP: L47 287,178; L48 317,390; L99 50.0M; L100 55.2M; L110 148.6M; L120 400M. All 120 nodes are buyable at level 120.
* Respec: right-click = `refund_talent`; allowed only for leaf nodes (no allocated node lists it in `requires`, else `has_dependents`); costs `TALENT_REFUND_CREDIT_COST = 3` reroll credits per node (client blocks below 3). No full reset found. Allocate reasons: `unknown_node, already_allocated, level_required, no_points, prereq`.
* Stacking: `sumEffects({delve:[ids],fortify:[ids]})` just adds `value` per effect over every id of both trees; `effLevel` adds into `effLevel[node.skill]`. Purely additive in the tree.

### A4. What each effect does (CODE; `G._getTalentEffects()` = sumEffects over BOTH trees)
| effect | formula / consumer |
|---|---|
| `moveSpeedPct` | fortify tree only. `totalMovementSpeed = movementSpeed(vigor) * (1 + [potion+telescope+gauntletMilestone+beacon+compass+talent+collector+ancient])`, `talent = moveSpeedPct/100` (additive with the others). `movementSpeed(v)=10+(v+1)*(0.1+0.0005v)` steps/s. Currently +2%. |
| `successPct` | added to `_successSources` in units of 1 percentage point: `successRate = min(100, 70 + max(0,lvl-req) + sources)` (SUCCESS_BASE 70, PER_LEVEL_OVER 1, PER_SOURCE 1; sources also count tools, banners/ledgers, sure beacons, collector). Over 100% the excess shortens actions: `(rate-100)*0.05` s. Only useful while the rate is under ~100% or as 0.05 s per overflow %. |
| `doubleGatherPct` | gathering skills (fish mine forage invoke farm plunder bard vigor): chance += pct/100; total cap `MAX_DOUBLE_GATHER` 0.85 (shared with tools 0.01/source, bounty beacons, collector, overflow). |
| `saveMaterialPct` | processing skills (cook smith craft imbue brew barter): keep-input chance += pct/100; cap `MAX_MATERIAL_SAVE` 0.55. |
| `actionTimeSec` | `_flatDurationReduction()` += value seconds. `duration = max(2, (10-(lvl-1)*.01) - 0.1*min(8,sources) - toolReduction - flat - successOverflowSpeed)`. Currently 0.51 s. |
| `skillingXpPct` | `getSkillXpBonus(skill)`: non-combat and non slay/delve/fortify skills, `+= pct/100` (additive with tools, pets, capes, collector, holiday). |
| `globalXpPct` | same function, every skill. From both trees (fortify enlightenment 13.25 total, delve revelation 10 total). |
| `fortifyXpPct` | `getSkillXpBonus('fortify')` only (Fortify XP from Fortress actions; scope "raid"). |
| `foodHeal` | `_computeHealBonus`: count += foodHeal, total capped `FOOD_HEAL_BONUS_MAX` = 20 together with pets and capes. |
| `barterPanelXp` | full barter panel XP = `floor(barterLvl*(10 + 10*(notes + barterPanelXp)))`; the single node counts as one extra Trader's Note. |

Read paths: combat reads (`getCombatBonus`, `getTalentCombat`, `_deriveDelve`, combat panels) pass `fortify:[]`, so **Fortify nodes never touch combat**; skilling reads (`_getTalentEffects`) sum both trees (the Delve tree only contributes its XP clusters there).

### A5. The Fortress itself (CODE, Constants)
`raids.json` id `gauntlet`, name "Fortress", `nodeId gauntlet_raid`, `waves:[]` (server-generated), single endless difficulty, party raid. Each player picks a gather/process role (`GAUNTLET_ROLES`: fish/cook -> health, mine/smith -> melee, forage/craft -> range, invoke/imbue -> magic, farm/brew -> defense) and deposits processed items at the centre to raise army stats (start stat 10; deposit value `round(2*1.35^tier)`; raw deposit divisor 3). Waves: first after 120 s then every 20 s; exchange interval 1.5 s; wave health `round(32*w*1.039^w*1.55^min(5,section)*1.06^max(0,section-5))` with `section=floor(w/20)` (past wave 100 growth 1.022^(w-100) replaces 1.039^w); attack `round(w*1.06^w)`; defense `round(1.5*w)`; `GAUNTLET_DEF_K` 600. Rewards: Banners at wave 20,40,...,140, Ledgers at personal deposit totals 800/2850/6050/17000/31750/53250/85000, per-wave rare roll (beacons, satchel), commons per 20 waves.
Fortify XP constants: `FORTIFY_XP_BASE=1`, `FORTIFY_XP_PER_WAVE=0.36`, `FORTIFY_XP_FAIL_FRACTION=0.25`, completion bonus `fortifyCompletionXP(w)=round(w^2)` (deepest wave squared); skill text: XP per action scales gently with wave. Exact per-action formula is server side (SPEC: `(1+0.36*wave)` per action, failures x0.25, then the `getSkillXpBonus` multiplier). Your record: best wave 44 (121.5 s), 103 runs (`G.raidStats.gauntlet`).
Whether in-raid actions apply the global-scope Fortify nodes (action time, success, double gather, save, move speed) is server logic (SPEC; cluster `scope:"global"` vs `"raid"` suggests global ones apply everywhere including the Fortress). Only `fortifiers_insight` is raid-scoped.

### A7. Planner algorithm
The graph is a rooted tree with unit costs and additive values, so the optimum for k points is the max-weight connected subtree containing the root with k non-root nodes: tree knapsack DP, `best[v][j]` = best weight choosing j nodes in subtree(v) with v taken; merge children by (max,+) convolution; O(n*k), n=120. Node weight = marginal objective (DPS %, XP/h, ...). Several effects are non-separable (success cap 100%, double gather cap .85, save cap .55, foodHeal cap 20, crit chance cap 1, floored 2x multiplier on effLevel), so run the DP on linear weights then re-score exact objectives (Part B function) on the top candidates or use greedy with path look-ahead. Exclude nodes with `requiresLevel` above the current level. Refunds cost 3 credits per node and are leaf-first, so treat the current allocation as fixed unless switching is worth it.

Per-node tables. parent = the single `requires` (n0 = starter); tier s/m/l; fortify momentum values are seconds shaved; mine = currently allocated.

## PART B. Expected player DPS using the game's own logic

### B0. Where the math lives
* Constants and primitives: `Constants` (bundle `y`; the wiki mirror `/wiki/tools/calc-constants.js` = `CalcConstants`, auto-generated from the same file, pure data and functions: `buildScore, maxHit, hitChanceFromScores, minHitFloor, damageReduction, finalDamage, attackInterval, critChance, critDamageMult, critDamage, ammoPenaltyScore, COMBAT_STYLE_MAP`). It is NOT a window global in the game page (only the bridge holds it as `Y`), but it can be fetched and evaluated, or hard-copied.
* Gear Calc: `/wiki/tools/gearcalc.js`, loaded by `/wiki/tools/gearcalc-embed.html`, opened via `U` (`Ua`: `U.CALC_URL`, `U.STORAGE_KEY='scapewatch_gearcalc_import'`, `U.buildSnapshot`). Its logic (`computeAttacker(att, def, style)`, line ~886; "Avg DPS" row at ~2967) sits inside an IIFE and nothing is exported. The only way to run it is an iframe plus the localStorage snapshot, which is what game-bridge.js `calcRefresh` does (1.5 s per read, writes localStorage). A hypothetical could be injected through `snap.delve`, but that is slow and has side effects, so reimplement (B2).
* Directly callable pure game function: **`window.CombatMath.computeAttack(attacker, defender)`** (shared/CombatMath.js, the same per-swing model the server uses and the Gear Calc inlines). It touches no state. It returns `maxHit, effectiveMaxHit, minHitFloor, critFloor, hitChance, reduction, critChance, critDamageMult, critMaxHit, attackInterval, damageBonus, atkRoll, defRoll...` but NOT average damage, DPS or the Delve `attackSpeedPct`. Avoid `CombatMath.resolveAttack` (uses Math.random). `Dashboard._killSeconds(taskId, ls)` wraps it (B3) and only writes its own 15 s cache `D._killSecCache`.
* Delve effects enter in four places: `G.getTalentCombat()` {maxHitBonus, minHitBonus, critChanceBonus, critDamageMultBonus, attackSpeedPct}, `G.getCombatBonus(skill)` (effLevel), `U._deriveDelve()` / snapshot `delve:{critChancePct,critDamagePct,minHit,maxHit,attackSpeedPct,effLevel{}}`, and the effective-level tooltip in the skills panel.

### B1. Formulas (CODE, calc-constants.js + gearcalc.js computeAttacker; numeric match in B2)
Constants: SKILL_MULT 2; HIT_BASELINE 0.6; HIT_SLOPE 0.003; HIT_FLOOR 0.1; HIT_CEILING 1; OVERFLOW_CAP 0.5; MAX_HIT_BASE 2; MAX_HIT_DIVISOR 5; REDUCTION_DIVISOR 10; REDUCTION_CAP 0.75; VIGOR_SLOPE 0.0025; VIGOR_REDUCTION_CAP 0.5; CRIT_BASE_CHANCE_PCT 5; CRIT_CHANCE_PER_SOURCE_PCT 0.2; CRIT_BASE_DAMAGE_MULT_PCT 120; CRIT_DAMAGE_PER_SOURCE_PCT 0.25; COLLECTOR_MAX_CRIT_CHANCE_PCT and _DAMAGE_PCT 10; SPIRIT_BASE_MODIFIER 1.1; SPIRIT_MODIFIER_PER_SOURCE 0.025; SPIRIT_DEPLETED_MODIFIER 1; SPIRIT_FACTOR_BASE 0.1, CAP 0.4; LIFE_HP_MULT 2; `COMBAT_STYLE_MAP[style]` -> {accSkill, strSkill, accBonus, defBonus, strBonus, ammoType?}: stab/slash/crush -> strike/heft + meleeStrength; range/crossbow -> sight/draw + rangeStrength; magic/wand -> focus/surge + magicStrength.

```
spiritMod  = spiritActive ? 1.1 + 0.025*spiritSources : 1.0           // player; mobs always 1.1
factor     = spiritMod>=1.1 ? min(0.4, 0.1 + (spiritMod-1.1)) : 0
buildScore(level, gear, bonuses) = floor(2*(level+bonuses)*(1+factor)) + gear       // bonuses are INSIDE the 2x multiplier
player bonuses(skill) = potion boost + getCombatBonus(skill)   // pets, capes, tools (chaos x2), max cape, Delve cape/pet, Delve-tree effLevel
A  = buildScore(accSkill lvl, equip[accBonus], bonuses_acc)
S  = buildScore(strSkill lvl, equip[strBonus], bonuses_str)
D  = buildScore(mob.dodge *(1-pen), floor(mob[defBonus]*(1-pen)), 0, mob spirit)
SD = buildScore(mob.defend*(1-pen), floor(mob[defBonus]*(1-pen)), 0, mob spirit)   // pen = weapon penetration, 0 unless Chaos/God weapon
ammo missing (usesAmmo && !hasAmmo): A = floor(A/2), S = floor(S/2)
maxHit     = 2 + floor(S/5) + talent.maxHit                                   // Onslaught
reduction  = min(0.75, floor(SD/10)/100)
raw        = 0.6 + 0.003*(A-D);  hit = clamp(raw, 0.1, 1);  overflow = clamp(raw-1, 0, 0.5)
minHit     = min(maxHit, max(1, floor(overflow*maxHit)) + talent.minHit)      // Cleave
interval   = weaponSpeed*(1 - min(0.5, (vigorLvl+vigorBonus+1)*0.0025)) * (1 - talent.attackSpeedPct/100)   // last factor: Gear Calc only (Swiftness)
critChance = min(1, (5+0.2*critSources)/100 + talent.critChancePct/100 + collector%*0.1/100 + extra.chancePct/100)
critMult%  = 120 + 0.25*critSources + talent.critDamagePct + collector%*0.1 + extra.damagePct
rolls k uniform in [minHit, maxHit]:
  normal(k) = max(1, ceil( floor(k*dmult)*(1-reduction) ))
  crit(k)   = max(1, ceil( floor( max(kk+1, floor(kk*critMult/100))*dmult )*(1-reduction) )),  kk = max(k, critFloor)
dmult      = 1 + critChanceDamagePct*critChance   (Syndicate/Phantom gauntlets; else 1)
avg        = (1-critChance)*mean(normal) + critChance*mean(crit)
DPS        = avg * hit / interval
kill time  = mob.life*2 / DPS  (+ respawn: COMBAT_BASE_RESPAWN_TIME 8 s, x2 off-slay, minus Alms reductions)
```
Delve tree mapping: `effLevel[skill]` -> +N to that skill's bonuses (so +1 level is worth about 2.0-2.2 score points); `minHit`/`maxHit` flat; `critChancePct`/`critDamagePct` percentage points; `attackSpeedPct` shortens the interval; `corruptChancePct` has no client consumer (server/slay corruption, SPEC); XP clusters irrelevant to DPS.

### B2. Self-contained pure function (VERIFIED)
Check: loadout `melee_3` vs `dire_golem`: this function = **10.9046 DPS**; the overlay's hidden-iframe Gear Calc reading for key `dire_golem|melee_3` = **10.9**. Inputs were taken from the game: skill levels, `getCombatBonus`, `getPotionBoosts`, `computeLoadoutStats`, `U._deriveDelve/_deriveExtraCrit/_deriveSpiritSources`, `getCritSources`, `getCollectorProgress`. Passive inputs (penetration, critFloorPct, critChanceDamagePct, mobPostReduction) mirror the Gear Calc but were not exercised (SPEC for Chaos/God gear).

```js
// Pure DPS model (mirrors wiki/tools/gearcalc.js computeAttacker). Needs: C = Constants (bundle `y`, same numbers as CalcConstants).
function gearCalcDps(C, inp) {
  // inp = {style, weaponSpeed, equip:{<acc/str bonus fields>}, lvl:{skill:level}, bonus:{skill:int}, pot:{skill:int},
  //        spirit:{active:bool, sources:int}, usesAmmo, hasAmmo, critSources, collectorPct(0-100), extraCrit:{chancePct,damagePct},
  //        talent:{minHit,maxHit,critChancePct,critDamagePct,attackSpeedPct}, passives:{critFloorPct,penetration,critChanceDamagePct},
  //        mob:{dodge,defend,<style>Defense, slayLevel, life}, mobPostReduction:0}
  var m = C.COMBAT_STYLE_MAP[inp.style] || C.COMBAT_STYLE_MAP[C.UNARMED_STYLE];
  var spMod = inp.spirit.active ? C.SPIRIT_BASE_MODIFIER + inp.spirit.sources * C.SPIRIT_MODIFIER_PER_SOURCE : C.SPIRIT_DEPLETED_MODIFIER;
  var sp = spMod < C.SPIRIT_BASE_MODIFIER ? {s:false,c:0} : {s:true,c:Math.max(0, spMod - C.SPIRIT_BASE_MODIFIER)};
  var eb = function(k){ return (inp.bonus[k]|0) + (inp.pot[k]|0); };
  var A = C.buildScore(inp.lvl[m.accSkill], inp.equip[m.accBonus]||0, eb(m.accSkill), sp.s, sp.c);
  var S = C.buildScore(inp.lvl[m.strSkill], inp.equip[m.strBonus]||0, eb(m.strSkill), sp.s, sp.c);
  var pen = Math.min(.95, Math.max(0, (inp.passives||{}).penetration||0)), pk = 1-pen;
  var mob = inp.mob, mobSp = {s:true,c:0};            // mobs: spirit active, capePet 0
  var eqD = Math.floor((mob[m.defBonus]||0) * pk);
  var D  = C.buildScore((mob.dodge||0)*pk,  eqD, 0, mobSp.s, mobSp.c);
  var SD = C.buildScore((mob.defend||0)*pk, eqD, 0, mobSp.s, mobSp.c);
  if (inp.usesAmmo && !inp.hasAmmo) { A = C.ammoPenaltyScore(A); S = C.ammoPenaltyScore(S); }
  var t = inp.talent, rawMax = C.maxHit(S) + (t.maxHit||0);
  var red = C.damageReduction(SD);
  var hc = C.hitChanceFromScores(A, D);
  var minF = C.minHitFloor(hc.overflow, rawMax); if (t.minHit) minF = Math.min(rawMax, minF + t.minHit);
  var cfp = (inp.passives||{}).critFloorPct||0;
  var critFloor = cfp>0 ? Math.min(rawMax, Math.max(minF, Math.floor(cfp*rawMax))) : minF;
  var vigor = (inp.lvl.vigor|0) + eb('vigor');
  var interval = C.attackInterval(inp.weaponSpeed, vigor);
  if (t.attackSpeedPct) interval *= (1 - t.attackSpeedPct/100);
  var xc = inp.extraCrit||{}, col = (inp.collectorPct||0)/100;
  var cc = Math.min(1, C.critChance(inp.critSources) + (t.critChancePct||0)/100 + col*C.COLLECTOR_MAX_CRIT_CHANCE_PCT/100 + (xc.chancePct||0)/100);
  var cm = C.critDamageMult(inp.critSources) + (t.critDamagePct||0) + col*C.COLLECTOR_MAX_CRIT_DAMAGE_PCT + (xc.damagePct||0);
  var dmult = 1 + Math.max(0, (inp.passives||{}).critChanceDamagePct||0) * cc;
  var post = Math.min(1, Math.max(0, inp.mobPostReduction||0));
  var postCut = function(v){ return post>0 ? Math.max(1, Math.floor(v*(1-post))) : v; };
  var n = rawMax - minF + 1, sN = 0, sC = 0;
  if (n <= 0) { sN = 1; sC = 1; n = 1; } else for (var k = minF; k <= rawMax; k++) {
    sN += postCut(Math.max(1, Math.ceil(Math.floor(k*dmult)*(1-red))));
    var kk = Math.max(k, critFloor);
    var cr = Math.floor(Math.max(kk+1, Math.floor(kk*cm/100)) * dmult);
    sC += postCut(Math.max(1, Math.ceil(cr*(1-red))));
  }
  var avgN = sN/n, avgC = sC/n, avg = (1-cc)*avgN + cc*avgC;
  return { dps: avg*hc.chance/interval, hit: hc.chance, minHit: minF, maxHit: rawMax, avgNormal: avgN, avgCrit: avgC, critChance: cc, critMultPct: cm, interval: interval, reduction: red, A:A, S:S, D:D, SD:SD };
}
```

### B3. How the game itself approximates it (VERIFIED numbers)
`Dashboard._killSeconds(taskId, ls)` (Dashboard, Route Advisor) calls `CombatMath.computeAttack` with `getTalentCombat()` bonuses and then uses `meanHit = (minHitFloor + effectiveMaxHit)/2`, `critFactor = 1-c + c*critMult/100`, `dps = hit*meanHit*critFactor/attackInterval`, kill = `life*2/dps`. Differences vs the Gear Calc: (a) ignores `attackSpeedPct` (Swiftness), (b) ignores the per-roll ceil / min-1 rounding and the crit `kk+1` floor, (c) spirit comes from `getDisplaySpiritMod()` (1.0 now, not 1.1). Results (melee_3): dire_golem game 9.98 vs Gear Calc 10.90 (-8.4%); savage_vampire 6.54 vs 6.64; feeble_zombie 11.90 vs 13.34. So the in-game kill-time projection is biased low for this account; use the B2 model for optimisation. Open: whether the real combat scene applies `attackSpeedPct` (test: while fighting, compare bridge `combat().player.interval` with `weaponSpeed*(1-vigorReduction)` and with the extra `(1-0.0275)` factor; the player was not in combat during this research).
