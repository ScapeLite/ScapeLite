# Changelog

## 0.4.1 (2026-11-09)

- **Clan board: cards for clanmates who do not run ScapeLite, made by the host.** New setting *Also Show Clanmates Without ScapeLite* (off by default) and a list *Clanmates On The Board* with a tick per clanmate, search and All / None. One PC, the host (the lease leader, or the only PC without a lease webhook), keeps a simple card for each clanmate with no ScapeLite card: online or offline, when they were last seen online, and total level and hiscores rank if the clan hiscores feature is on. Members who use ScapeLite keep their own live cards; they announce themselves on the lease, so the host makes none for them and removes the one it made when they start. After a host change the new host edits the same cards. Guide: docs/CLAN-STATUS-BOARD.md.
- **Team settings: set the Discord features up once, everyone gathers them.** New page 6 of the Discord setup wizard (and Settings, Plugins, Chat Relay, Team Settings). One person publishes ping roles, hiscores rules, digest times and raid rules to the shared lease webhook; everyone else presses Gather, sees what differs from their own, ticks what to take and can undo it. Export and Import as text or file work without a lease webhook, and an optional "keep in sync automatically" (off by default) applies newer versions for you. Webhook addresses never travel unless you tick it and confirm; the lease webhook, the several-users mode and your own looks never do. Guide: docs/DISCORD-TEAM-SYNC.md.
- **Relay lease: the message says when it was last written, and a change of leader is logged.** The lease message in the private channel now reads "leader <name> · last written <date> (<n> minutes ago)" (Discord shows it in each reader's own time zone). The watcher log gets a line whenever the leader changes ("the leader changed from A to B"). The leader name is the in-game name and is re-read every 30 seconds.
- **Info Bars never overlap their text on a narrow window.** The bars are now fitted by measuring the real modules, each bar on its own, whenever the width or the content changes. Free room is used first (spacers shrink), then the longest module gives up labels and secondary parts ("12.3k XP/hr" becomes "12.3k"), then long numbers are abbreviated, then gaps and padding shrink, then flexible text gets an ellipsis (the hover card keeps the whole text), and only as the last resort the lowest-priority modules move into a **…** menu at the end of the bar. The bell, Hit points and the panel buttons are never hidden. Right-click a module, *When the bar is too narrow*, to hide it first or never hide it. Order, priorities and test: `docs/INFO-BAR-FIT.md`, `npm run test:barfit`.
- **Discord relay: it now works with the game's default chat.** The relay only read the chat lines the game draws, so anyone whose chat had a channel greyed out (for example Global) or a message type filtered away (drops, levels ...) relayed nothing of it; the old guide even told you to switch those types on. ScapeLite now also reads the lines the game keeps but hides, with no double posts, and lines that were already there when ScapeLite started stay history (switching a filter on does not flood Discord). New check: `npm run test:relay-collect`.
- **New: Discord setup wizard (Settings, Plugins, Chat Relay, Open wizard; or the ScapeLite menu).** Five pages: before you start, channels and webhooks, roles and pings, in the game, several PCs. Each channel has a masked field with a check of the address, a status (not set up, saved, works, error with the reason), the on/off switch and a **Test this channel** button that sends one clearly labelled test message (at most one per 10 seconds). A saved webhook is never shown again, only replaced or removed. The long guide is `docs/DISCORD-RELAY-SETUP.md` (channels table, roles table, troubleshooting). New check: `npm run test:discord-setup`.
- **The ScapeLite default layout is redesigned to look clean.** Testers found the first version messy: columns of different widths, panels at four different scales, ragged edges and too many windows. Now: one 8 px grid, one column width (the task queue, XP tracker, the game's windows and pinned cards are all exactly as wide), one scale for every ScapeLite panel, and two docks on the right that share their top, their split line and their bottom edge. Only the task queue, the XP tracker and the chat are open; the other panels (Goals, Drop Luck, Tree Advisor, Advisor, Locations and Free Pips) are placed as one tab group but closed, and open in their spot from the ScapeLite menu. The Route Advisor keeps its own handle on the right edge, which the docks leave clear. Back to my old layout now also reopens the panels that were open before. The welcome tour has a "Your panel layout" step with a button (nothing moves unless pressed). Preview: `docs/default-layout-preview.png`.

## 0.4.0 (2026-10-28)

- **Active Potions: point at one food or potion in the hover card for its exact numbers.** Food shows the calculation with your real values: base heal, each bonus (Life pet, capes, talents, up to the cap), spices, the heal per bite `floor((base + bonus) x spice multiplier)`, what your stock is worth in HP, bites from empty to full, and the eat cooldown (hot sauces counted). Potions show the stat they give (combat levels, walking speed, extra chest rolls, spirit restored), how long they last (base charges x your potion efficiency from Alms), what is left, and the rule that only the first potion of a kind is active. All read from the game's own data (`foodInfo` and `potionInfo` in the bridge); nothing is pressed.
- **Barter: with no charges left the card is greyed out.** The Barter card (hover and pinned) greys its rows and says "No charges left", and the Barter button in the Info Bar reads "No charges" in grey, like the game's own dark overlay. It goes back to normal as soon as charges return.
- **Drop Luck Tracker overhaul.** Two main tabs now: **Overview** (the big luck verdict with your percentile, obtained against expected for each category, and the most overdue drops) and **Detailed**, whose sub-tabs are Pets & Tools, Unlocks, Mobs, Delve and Fortress. Drag a sub-tab to reorder it (a marker shows where it lands; Shift+Left / Shift+Right moves the focused one; right-click the row to reset the order); the order, the last main tab and the last sub-tab are remembered, and old saved tabs map on (the Luck tab became the Overview, Raids became Delve). Every sub-tab starts with one small line in the verdict's colour (`Luck: Lucky · 83rd percentile · 4 obtained / 2.5 expected`) instead of the big card, and shows only the filters that fit it: Pets & Tools has a Pets | Tools | All switch, a search and an owned / missing filter (the Overview's Lucky tools row opens the Tools part); Unlocks has category chips (Tools, Conduits, Ancient shards, Chaos shards, Dungeon extras), filters and a search; Mobs and Delve search drop names too. Every drop with a 1-in-N rate has a chart icon button: hover it for the game dashboard's "chance of having it by kill count" graph as a hover card (your kills marked, 50/90/99% marks), click it to pin the graph under the drop (remembered per drop). Delve lists the dungeons and the Chaos Dungeon with everything the game's Drop Table shows for it (milestones, tiered special drops by wave band, tools from wave 121, Chaos components from wave 101, God gem and components from wave 121) against your collection; the Fortress tab gets the same list for its tiered rares. The game publishes no per-kill chance for these, so none is made up and Chaos and the Fortress get no per-run luck rating. `npm run test:drop-luck`.
- **New: Advisor panel (open it from the ScapeLite menu; an optional Info Bar module "Next action" shows the top action).** One place that says what to do next, how and where. It reads the Route Advisor, Lever Advisor, Tree Advisor, Goals and Locations and Free Pips, turns what each says into the same kind of action, puts the best one on top and keeps the rest in tabs, with how sure each one is (exact, measured, modelled). It only reads and shows; it never presses anything. Lever advice follows the roll model check (`docs/ROLL-MODEL-CALIBRATION.md`): ranked by rate; location levers are suggested only as walking, with free pips first. The diary is never advised. Design and rules: `docs/UNIVERSAL-ADVISOR.md`. `npm run test:advisor`.
- **New: Locations and Free Pips panel (open it from the ScapeLite menu).** The diary fills up by itself and each tier gives free node-lever pips at the locations next to that bank; this panel says where to spend them. It rates every location of every skill by its walking distance to the nearest bank (good, middling, bad at your real speed), shows how often it is rolled and how often you did it in your last 200 tasks, and recommends lever moves that cut walking: bad locations down, good ones up, free pips first, with what a pip costs otherwise. The saving is an estimate (half the straight difference in distance) and affects walking, not the XP rate directly. Diary progress and the credit pools are there as reference. It only reads the game. First phase of the Universal Advisor (`docs/UNIVERSAL-ADVISOR.md`, `docs/ADVISOR-NOTES.md`). `npm run test:diary`.
- **Chat commands: type `/sl help` (or `/scapelite help`) in the chat.** Eight commands, plus `/sl plugins`: `help`, `version`, `status`, `refresh` (reloads ScapeLite's plugins in the page), `plugin <id> on|off`, `relay status`, `digest preview` and `hiscores check` (a dry run of the clan rank lookup: it posts nothing and leaves the last-post baseline alone). Replies are shown only to you, as an `SL` line in the ScapeLite chat or as a toast when the chat panel is shut; they are never saved to the chat log and never reach Discord. A `/sl` line is never sent to the game as chat, and any other `/word` goes to the game as before. A fixed allow-list decides what can run, bad or too frequent requests get an error reply, and nothing here can post to Discord. Design and status: `docs/CHAT-COMMANDS.md`. Test: `npm run test:commands`.
- **Chat: an SL button next to the channel buttons.** Global, Nearby, Raid, Friends, Clan, Game and now SL. SL shows or hides ScapeLite's own lines (the `/sl` replies and lines marked as ScapeLite's). The choice is remembered. A reply that arrives while SL is off is never lost silently: the button shows a count and a toast shows the text.
- **The welcome tour starts with the look chooser.** Step 1 offers Full Vanilla, Combination and ScapeLite only; picking one applies it at once with an Undo, and skipping is remembered so it is never asked twice. Step 2 describes the chosen look, and the rest of the tour adapts to it (in Full Vanilla the Info Bar and Alerts steps and the ScapeLite menu sentences are left out). The status light is never hidden by any look and the game's side bar always stays. The old chooser window is still the fallback when the tour is switched off. Test: `npm run test:onboarding`. See `docs/ONBOARDING.md`.
- **Panel sizes show the real on-screen scale.** The right-click size chips, the "Reset size" item and the drag readout now count from the game's own base size, so 100% is what the game draws before it scales its whole interface to your window (at a UI zoom of 1.27 the old "100%" was really 127%). Stored sizes are unchanged, nothing moves.
- **Fix: the game's empty invite tray no longer shows as a tiny dark bar with a "move" handle.** The tray is hidden while it holds no invite, and the handle only appears with an invite in it.
- **Fix: someone who left the clan no longer shows up in the next Activity Digest.** The member list already followed the clan roster, but the digest's buffer of the current period kept what that person had done earlier. Every poll now drops buffered activity of anyone who is not in the clan roster.
- **Lucky slay tasks show their Luck XP progress too**, like lucky skilling tasks: the tooltip gets a Luck block (gain, time, XP an hour, Luck level progress, before and after) marked "lucky bonus".
- **Fix: a Lucky slay task's XP was over-estimated by about a fifth.** Only Slay XP and the XP of the skill you train are doubled (the game says so, and nine logged lucky tasks confirm it); Life, Spirit and the second combat skill are not. The tooltip, the Route Advisor and the queue now count them once. The queue's option card also says "Lucky task: 2x XP and rewards" instead of "Lucky tool chance: yes".

- **Cards: one shared way to stay in step with the game, a test harness, and the card code out of ui-bar.js.** Basic card bugs kept coming back (Equipment toggles that did not move, Barter Charm and Reroll lag, the task queue refusing with "out of date") because every card had its own refresh logic: a 1 s poll, lists of delayed re-renders after a click, "never redraw under the pointer", a Barter special case. Now `overlay/card-sync.js` is the only mechanism: one MutationObserver per watched game panel (attached only while a card for it is open or shown, noise from ScapeLite's own marks filtered, at most one notification per 250 ms), a once-a-second data poll for the queue, a 5 s "follow the game" window after any click that is handed to the game (changes then redraw at once, even under the pointer, and the control keeps its hover and keyboard focus), and ONE redraw rule (never while a button is held down or a box is being typed in; a plain change waits while you point at a control and lands when the pointer leaves). The Equipment, Barter, Friends, Quests, Inventory, Skills, Diary and Chat cards and the task queue use it; the per-card timers are gone. The model builders of the cards moved from `ui-bar.js` to `overlay/cards/<name>.js` (new core plugins `card-sync` and `cards`; the installer packs `overlay/cards`). The game does not redraw its hidden task queue panel: before any queue action the layer calls the game's own redraw (read only), as before. Fix in passing: `__ccDom` served an empty element list during the first second of a page. Write-up: `docs/ARCHITECTURE-CARDS.md`.
- **`npm run test:cards` and `npm run lint:forwards`.** The harness opens every card with real mouse events on the live game and compares it with the game (counts, labels, on/off states), presses only the Equipment display toggles (and restores them), and checks afterwards that settings, prototypes and observers are as they were. Buttons that spend or change game state (Barter Reroll/Buy/Charm, queue select) are tested against a fake game in a private hidden Electron window with the real overlay files injected. The lint fails when a new unmarked `.click()` / `dispatchEvent` appears in overlay code (82 existing sites are counted in `scripts/forwards-baseline.json`, not refactored).
- **ScapeLite looks and a first-run chooser.** Three looks in one table (`overlay/presets.js`): Full Vanilla (the game as it is), Combination (the Info Bar next to the game's panels) and ScapeLite only (game panels hidden; bottom bar with chat, panel buttons that open ScapeLite's cards, hit points bar). A new install is asked once (skippable, remembered, the welcome tour waits for it); an existing install is never asked and never changed. Settings > Plugins > ScapeLite Core > ScapeLite Look reopens it, shows the current look (Custom as soon as you change a single option) and has Undo. New helper calls: `__ccPluginSettings.setBundle`, `__ccBar.applyConfig`. The default Info Bar now has the Panel buttons module. Write-up: `docs/ONBOARDING.md`.
- **Fix: the Info Bar's "Open/Hide the game's original panel" item asked twice.** It kept its own flag, so after closing that game panel by hand it still offered Hide. It now reads whether the panel is really on screen when the menu opens, and the flag follows when the panel disappears.
- **Task queue: hover a card or an alternative to preview its route on the World Map.** While the game's World Map window is open, hovering a queue card (its picked task) or an alternative tile in the pop-out shows the route to that task, drawn by the game itself exactly as when you hover a task in its own Tasks panel: your hover is passed to the game's matching tile (nothing is drawn, clicked or queued by ScapeLite). Skipped when the map is closed, for the current task, while dragging, and when the game's hidden queue panel is out of date (the route would belong to another task). Switch: Plugins > Queue and Tasks > Hover A Task To Preview Its Route On The World Map.
- **New alerts: free quest slots and unspent barter charges.** Both are off by default (Plugins > Alerts) and quiet: an alert appears only after two checks in a row, and once dismissed it stays away until the situation changes (a different number of free slots or open quests; a new barter roll). Free quest slots: you hold fewer than the game's 5 active quests and at least one more quest is open to you. Barter charges: the Barter panel header still shows charges on the current roll. "Go there" opens the game's Quests or Barter panel; nothing is begun or bought. They appear in the bell, its filter menu and the Info Bar's alert count.
- **Chat: links, world tag, Tab and the rules dialog.** In ScapeLite's Chat panel and the pinned Chat card: web addresses (http and https only) are clickable links that open in a new tab (text is never inserted as HTML); the game's W-number world tag shows before names in World chat (and no longer leaks into the message text); the card also shows crowns and badges; Tab in the chat panel's message box steps to the next send channel like the game's box; when the game's chat-rules dialog stops a message (before the rules are accepted) the box says so, keeps nothing half sent and puts the focus in the game's own box; accepting and sending stay yours. Switches: Plugins > Panels > Chat: Clickable Links / World Tag / Help With The Chat Rules Dialog / Tab Changes Send Channel.
- **Watchdog: ScapeLite notices when one of its parts is not running, logs it and restarts it.** Last night the watcher died, the supervisor and tray were already gone, and the Discord relay posted nothing all night. Now the tray checks the supervisor and watcher every minute (lock file, pid alive, and that the pid is really that program, since Windows reuses pids) and the watcher writes a heartbeat so a process that lives but whose loops stopped is caught too. Every exit and restart is logged to `Logs/System` (`[supervisor]` / `[tray]`, lines starting `PROBLEM:`). Policy everywhere: restart at once, again about 5 minutes later, then every 10 minutes without log spam. A watcher stopped from the dashboard is left alone. The tray menu has a `Last problem:` line. Details, limits and proposals (scheduled task, push alert): `docs/WATCHDOG.md`; `npm run test:watchdog`. Needs a restart of the service and the tray app. This replaces the supervisor's earlier retry rule (five quick retries, then once a minute).
- **Installer packs an allow-list, never user data.** `build.files` now starts from nothing and names product files one by one (no `overlay/**`, no `node_modules`, no docs beyond the three guides, no `.vbs`), so a private or new runtime file can no longer be packed by accident (the old deny-list would have shipped the test webhook file and the lock files). A guard (`scripts/lib/package-guard.js`) runs on the packed app before the installer is made and fails the build on a forbidden file, a webhook URL, a bot-token-like string, a secret-looking value, a real Windows user path, a bundled config that is not hollow, a personal-name deny-list term (kept outside the repo), an oversized file or a `require()` the package cannot resolve. `npm run verify:package`, `npm run test:package`; the publish script scans the files it is about to publish too. Details: `docs/PACKAGING.md`.
